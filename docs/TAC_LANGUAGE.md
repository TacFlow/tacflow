# TAC Language — The Agentic DSL

> *"TAC is not a language for writing code. It is a language for thinking like an agent."*

## Overview

TAC (TacFlow Agentic Code) is a domain-specific language designed from the ground up for autonomous AI agents within the TacFlow swarm ecosystem. Unlike general-purpose programming languages or natural language prompts, TAC provides a **deterministic compilation layer** that combines LLM flexibility with compiler-grade predictability.

## Compiler Pipeline

```
Source (.tac) → Lexer → Parser → AST → Semantic Analyzer → Compiler → Flow JSON (DAG)
```

### 1. Lexer
Tokenizes `.tac` source into meaningful tokens — keywords, identifiers, operators, literals, and trust annotations.

### 2. Parser
Builds an Abstract Syntax Tree (AST) from the token stream. Handles expressions, statements, flow constructs, and agent directives.

### 3. Semantic Analyzer
Validates the AST against the **Trust Types system** and flow rules:
- Checks variable provenance at every usage point
- Validates agent capability references against the swarm registry
- Ensures DAG acyclicity at the semantic level

### 4. Compiler
Transforms the validated AST into a deterministic **Flow JSON** — a Directed Acyclic Graph (DAG) that the TacFlow engine executes with guaranteed termination.

## Trust Types System

The crown jewel of TAC. Five levels of variable provenance validated at **compile time**:

| Trust Level | Tag | Description | Example |
|:---:|:---:|:---|---:|
| 0 | `@user` | Direct from human input | `name: @user string` |
| 1 | `@verified` | Cross-checked against a trusted source | `email: @verified string` |
| 2 | `@inferred` | LLM-generated, not yet verified | `summary: @inferred string` |
| 3 | `@system` | Generated by the engine itself | `session_id: @system string` |
| 4 | `@swarm` | Consensus from multiple agents | `decision: @swarm string` |

**Why this matters:** An agent cannot execute a destructive action (send email, approve payment, delete data) using `@inferred` data without explicit human confirmation. This is enforced at the compiler level — not through prompt engineering.

## Canonical Round-Trip Formatting

Every `.tac` file can be:
1. Parsed into AST
2. Formatted canonically
3. Re-emitted as identical `.tac`

This guarantees:
- **Auditability:** Two semantically identical files always produce the same canonical form
- **Diffability:** Meaningful code reviews on agent flows
- **Version Control:** Standard Git workflows for agent behavior

## Auto LoRA Dataset Generation

Every execution of a TAC flow automatically generates a structured training record:
- **Input:** The validated AST + Trust Type annotations
- **Output:** The execution trace + decisions made
- **Format:** Ready for LoRA/QLoRA fine-tuning pipelines

This means **every flow execution improves future model performance** — no manual dataset curation required.

## Example: Hello Agent

```tac
flow hello_agent {
    trigger: on_message

    step greet {
        input: @user name
        action: llm.generate("Greet {{name}} warmly")
        output: @inferred greeting
    }

    step respond {
        input: @inferred greeting
        action: message.send("{{greeting}}")
        trust: require @user for send
    }
}
```

## Example: RAG Search with Trust Validation

```tac
flow rag_search {
    trigger: on_query

    step search_memory {
        input: @user query
        action: memory.hybrid_search("{{query}}")  // BM25 + Vector + Graph
        output: @verified results
    }

    step validate {
        input: @verified results
        action: trust.validate_source("{{results}}")
        output: @verified validated_results
    }

    step respond {
        input: @verified validated_results
        action: llm.generate("Answer using: {{validated_results}}")
        output: @inferred answer
    }
}
```

## Example: Multi-Agent Delegation

```tac
flow multi_agent_delegate {
    trigger: on_complex_task

    step analyze {
        agent: sentinela
        input: @user task
        action: security.analyze_threat("{{task}}")
        output: @verified threat_level
    }

    step research {
        agent: fluxo_criativo
        input: @user task
        action: research.deep_dive("{{task}}")
        output: @inferred research_data
    }

    step decide {
        input: @verified threat_level, @inferred research_data
        action: swarm.consensus("safe_to_proceed", [sentinela, fluxo_criativo])
        output: @swarm decision
    }

    step execute {
        input: @swarm decision
        condition: "{{decision}} == safe"
        action: task.execute("{{research_data}}")
        output: @inferred result
    }
}
```
